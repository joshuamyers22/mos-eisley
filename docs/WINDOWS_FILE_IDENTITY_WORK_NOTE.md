## Frozen eligibility algorithm

GetFileType must report disk. NtQueryVolumeInformationFile class 4 supplies
FileFsDeviceInformation from the handle: disk (7) or disk-filesystem (8) device
type; allow only read-only, mounted, autogenerated-name, secure-open, PnP and
appcontainer-traversal flags.
PnP is 0x800; 0x200 is deprecated orderly removal and is refused. Portable-device
0x40000 and both legacy/extended removal-policy bits also refuse.
Unknown, removable, floppy, write-once, remote, virtual, Terminal Services, WebDAV,
portable and clustered characteristics refuse. Then
GetVolumeInformationByHandleW must report NTFS. FileStandardInfo must succeed
before FileIdInfo. No namespace/drive-letter lookup and no legacy identity API.
Device flags are observations, not proof of DACLs, safe reparse handling, physical
hardware provenance or stable future storage. Those remain separate qualification
and secure-opening contracts.

The native volume query documents final completion status. An unexpected
STATUS_PENDING is refused; one process-lifetime quarantine retains its output
buffers and disables further device queries, preventing deferred native writes
into freed storage or unbounded pending-buffer retention. No borrowed-handle
wait, cancellation or mutation is introduced. The retention pair is allocated and
retained before native entry; an exception before confirmed completion also keeps
that one pair and disables further queries.
