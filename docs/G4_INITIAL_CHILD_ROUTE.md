# G4 real initial coding-child route

The initial-child route is separate from the correction cycle. An enrolled
creator first signs the approved plan and creator tests, a reviewer signs custody
of the blind package, and the creator signs a bounded child assignment. A
separate creator-signed dispatch order names the exact assignment, base revision,
owned path, creator-test view, brief, criteria and immutable container image.
The read-only preview verifies signatures, package references, policy time,
committed Git bytes and a clean base worktree before exposing the exact offer.

Dispatch consumes an assignment-keyed claim before calling a generator. A live
generator additionally requires a short-lived creator-signed provider grant
binding the exact offer, stateless JSON request, model/effort, spend policy,
ledger and image. The shared ledger reserves the maximum before a request-bound
no-network worker reaches the trusted host transport. It permits one token count
and one provider request with no automatic retry. A malformed response can incur
a settled charge or retain an uncertain hold, but cannot become a signed child
proposal. The host parses bounded JSON, computes file digests, checks owned
existing paths and usage, then signs with the enrolled machine child key. An
offline no-mount worker and the host independently validate the proposal.

The dispatch receipt and private production receipt replay the signed links,
claim, source, contained result, provider response, audit chain, ledger entry and
usage. They grant no Git write, candidate test, final whole-suite run, review,
creator acceptance, merge, release or activation. Each downstream action needs
its own exact authority. The source worktree stays at the approved base.

The provider may return bad code. Qualification requires separately authorized
integration, tests and review of the actual integrated commit. One human signer
is disclosed; the machine child key is distinct from Joshua's creator key.
