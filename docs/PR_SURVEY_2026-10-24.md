## Findings and corrections

1. Runtime requirements in dependency PRs omit transitive lock changes.
   #331 package CI explicitly fails because pydantic 2.14.1 requires
   pydantic-core 2.50.1 while the export retains 2.46.5; source CI also rejects
   its stale export. #330's export retains httpx2 2.13.1 while its lock selects
   2.16.0. Regenerate the entire export from the combined frozen lock, rather than edit top-level
   package lines alone. Existing `tools/verify_export.py` guards this class.
2. #325 already has passing GitHub checks, but its PR evidence checklist and
   merge-preparation note still describe a running gate. Record current combined
   validation before integration; retain its explicit historical uncertainty.
3. Anthropic 2.0 enables SDK tracing by default and accepts ambient environment
   configuration that can capture request content. Explicitly disable SDK spans
   and trace propagation in the ephemeral transport. Raise the supported SDK
   floor to 2 because older SDKs do not support this constructor option. An
   offline real-SDK/HTTP-mock regression enables content tracing in the environment
   and verifies a successful single request without tracer access or trace headers.
   SDK 2 also defaults to API version 2026-10-21. Its documented Messages removals
   affect sampling parameters/document/citation inputs absent from this adapter's
   text/tool/reasoning payload; focused translation and SDK tests remain passing.
   Sources: [SDK release](https://github.com/anthropics/anthropic-sdk-python/releases/tag/v2.0.0),
   [API versioning](https://platform.claude.com/docs/en/api/versioning).
4. The installed-wheel runner uses an explicit test selection. Add the Anthropic
   provider module so its SDK compatibility and ambient-tracing regression run
   from the installed artifact as well as source. Startup regression modules and
   the capture helper are already included by #325.

## Tracing boundary review

The protected assets are owner prompts, provider responses and trace identities.
The dependency upgrade connects the SDK to ambient OpenTelemetry configuration;
an embedding process or configured tracing provider could receive message content
without Mos's explicit selection. The correction removes SDK span emission and
context propagation rather than introducing another destination. The behavioral
test exercises the actual SDK against an offline HTTP mock under content-enabled
environment settings. Third-party HTTP instrumentation installed by an embedding
application and live provider behavior remain outside this narrow SDK control.
No credentials, provider calls, security policy or approval mechanisms change.
