# G4 allowlisted implementation binding

The second offline G4 slice binds one canonical frozen reviewer-test package to one
exact implementation tree and one deliberately non-executable adapter description.
It produces an immutable, content-addressed binding record without importing source,
executing tests, invoking Git, writing the implementation, or granting downstream
authority.

This is a binding-validation boundary, not itself the test runner. The separate
[isolated execution/count boundary](G4_ISOLATED_TEST_EXECUTION.md) now consumes the
record without enlarging its authority. `binding_validated=true`
means the identities and declarative surface agree. The record keeps
`implementation_binding_authorized=false` because possession of a prior record does
not authorize creating a replacement binding. Test execution, repository/VCS writes,
network, credentials, provider dispatch, correction and acceptance are also literally
`false`.

## Manifest and complete tree identity

`ImplementationBindingManifest` requires:

- the SHA-256 identity of one canonical frozen reviewer-test package;
- a 40- or 64-hex source-revision claim;
- unique, sorted, non-overlapping source roots;
- every regular file under those source roots, classified as Python implementation
  source or an implementation resource;
- at least one exact dependency lock and one exact build-metadata file outside the
  source roots; and
- one sorted direct-symbol adapter allowlist.

Every file declaration fixes path, role, media type, byte count and SHA-256 digest.
The binder walks source roots through directory file descriptors without following
symlinks. Undeclared files, omitted resources, hard links, duplicate inodes, special
files, generated bytecode, excessive depth/entries, traversal, byte drift and
mid-read mutation fail closed. The binding record hashes the complete declaration
set with the source revision as `implementation_tree_sha256`.

The dependency and build declarations bind the exact files named by the reviewed
manifest. No generic Python tool can infer every project-specific dependency input;
the manifest reviewer remains responsible for confirming that the declared lock and
build files are the complete build surface. The source revision is likewise a bound
claim, not proof that Git produced the tree. G4's trusted VCS/E2 gate must establish
that later.

## Declarative adapter

Reviewer Python files use only explicit imports such as:

```python
from mos_eisley_reviewer_adapter import parse_record
```

Each imported name must have exactly one `DirectSymbolBinding` to a top-level symbol
defined in a declared Python source file. The target module must be the canonical
module derived from the file path and its declared source root. The binder scans all
Python content in the frozen reviewer package—not only files labeled `test`—and
requires its adapter imports to equal the allowlist. Direct static imports of a
target implementation package, wildcard adapter imports and whole-module adapter
imports are rejected.

The adapter contains no Python body. Its contract fixes wrapper code, monkeypatches,
result substitution, exception translation, discovery overrides and test-result
interception to `false`. A later trusted isolated runner may materialize only these
direct imports. It must not accept an executable replacement adapter.

AST inspection proves the common syntactic surface, not arbitrary Python semantics.
The isolated known-good/known-bad controls now exercise the exact adapter and bound
material, but they are not a general semantic proof or execution authority here.

## Create and replay-verify

Keep all inputs and the output outside the implementation root, then run:

```sh
uv run --frozen mos g4-bind-reviewer-implementation \
  --manifest implementation-binding-manifest.json \
  --reviewer-package frozen-reviewer-package.json \
  --implementation-root clean-implementation-tree \
  --output immutable-implementation-binding.json
```

The binder checks that the reviewer package is canonical and hashes its bytes before
and after implementation inspection. Any difference fails. The new private output
is mode `0600` and never overwrites an existing path.

Replay verification re-reads the current package and implementation tree and must
reconstruct the exact record:

```sh
uv run --frozen mos g4-verify-reviewer-implementation-binding \
  --binding immutable-implementation-binding.json \
  --reviewer-package frozen-reviewer-package.json \
  --implementation-root clean-implementation-tree
```

The resulting hashes identify evidence. They do not authenticate the manifest
reviewer, attest Git custody, execute tests, or accept an implementation.
