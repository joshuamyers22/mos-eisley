# Example advisory engineering guidance

This example is a project choice. Inspecting it does not attach it, accept its
recommendations as requirements, or grant execution authority.

## ENG-001

Prefer simple, maintainable code; earn complexity with evidence.

## ENG-002

Measure correctness, relevant efficiency, and whole-task cost together.

Project requirements, overrides, role-specific inclusion and accepted departures
must be established through the later trusted binding workflow.
